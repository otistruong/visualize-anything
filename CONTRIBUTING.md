# Contributing

Bug reports, corrections to the examples and new examples are welcome. Open an issue first for anything larger than a fix, so the approach can be agreed before you spend time on it.

## Setup

You need Node.js 18 or later. There is nothing to install.

```bash
npm test          # validate examples, check generated files, run offline evals
```

## Where things are

- `skills/visualize-anything/` is the skill and the only source of truth. Everything an agent needs is inside it.
- `examples/*.html` are built from `skills/visualize-anything/examples/*.json`. Never edit them by hand.
- `.claude-plugin/`, `plugin.json` and `adapters/` are generated by `scripts/sync.mjs`. Never edit them by hand.
- `evals/` tests what an agent does with the skill. See [evals/README.md](evals/README.md).

## Making changes

| You changed | Then run | And commit |
| --- | --- | --- |
| `SKILL.md` frontmatter or `package.json` version | `npm run sync` | the regenerated adapter files |
| `assets/player.html` or an example spec | `npm run build` | the rebuilt `examples/*.html` |
| the spec format | update `references/spec.md`, `scripts/validate.mjs` and, if the scene changes, the geometry block shared by the validator and the player | all of them together |
| anything | `npm test` | |

CI runs the same checks and fails if a generated file is out of date.

## Changing the player

- One file, no dependencies, no network requests, no build step. This is the point of the project.
- Check it in a real browser: every step of every example, light and dark, a desktop width and a 390 px wide phone. Look at the result, do not only run it.
- All text from a spec is inserted with `textContent`. Do not add a path that puts spec text into `innerHTML`.
- The scene geometry (the projection for both views, shape and tile sizes, and the placement of labels in the 2D plan) is one block of code that appears in both `player.html` and `validate.mjs`, between the `shared geometry: start` and `shared geometry: end` comments. Change both copies the same way; `scripts/check-docs.mjs` fails if they differ.
- Check both views (the 2D / 3D buttons or `V`), and switch while a token is moving. Adding `#step=4&view=2d` to an example's address opens it there.

## Adding or correcting an example

- Follow `skills/visualize-anything/references/method.md`. Every fact needs a source you can point at, listed in `sources`.
- The spec must pass `validate.mjs --strict`.
- Use documentation values only: `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`, `example.com`. No real hosts, credentials or personal data.
- If you are correcting a fact, quote the passage of the source that shows the current text is wrong.

## Changing the skill's instructions

- Keep `SKILL.md` under 200 lines; detail goes in `references/`.
- Keep the frontmatter to `name`, `description` and `license` so that every agent accepts it. The description must stay under 1024 characters.
- If you change when the skill should activate, update `evals/triggers.json`. If you change what the agent should do, update `evals/cases.json`.

## Style

Plain, direct writing. No marketing language and no emoji, in code comments, documentation and example text alike.
